# 项目结构与安全整理

Eugene Desk 的网站源码、个人资料和临时产物分开维护。目录整理不改变路由、存档键名或备份格式，也不把本地文件上传到线上。

| 位置                                             | 用途与规则                                                                               |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `src/routes/`                                    | 页面与路由入口。                                                                         |
| `src/components/`                                | 书桌界面；保持现有六语和移动端行为。                                                     |
| `src/lib/`                                       | 存储、备份、日期、课表与 GPA 规则；旁边的测试固定兼容边界。                              |
| `src/data/`                                      | 地点、学区、校历等业务数据。                                                             |
| `public/brand/`                                  | 网站实际使用的品牌资源；不是 Illustrator 源文件目录。                                    |
| `scripts/`、`.github/workflows/`                 | 项目测试、构建及发布验证；`npm test` 是全量测试入口。                                    |
| `docs/`                                          | 维护与历史记录。本页是目录索引；改版/修复进度见 [REDESIGN](REDESIGN-2026-10-03.md)。     |
| `eugene-desk-all-code/`                          | 本机文本副本与恢复快照。用 `sync.py` 生成，不手改分卷、不提交；每卷不超过 130,000 字节。 |
| `screenshots/`、`verification/`                  | 本机截图、合成测试文件和验证记录。保留历史证据路径，不部署。                             |
| `artifacts/`                                     | 本机历史交付和素材；`artifacts/README.md` 说明分类，整理清单支持按哈希恢复。             |
| `Eugene Desk Logo/`、`申请材料/`、`attachments/` | 设计源文件、申请材料与用户附件。不是可自动清理的缓存；保留原位，不提交。                 |
| `node_modules/`、`.vercel/`、`.tanstack/`        | 依赖和构建/项目状态，不通过手动挪动来整理。构建时由原有工具管理。                        |

## 保留的边界

- `.env*`、Git 历史和项目指令不移动、不输出内容；二进制与密钥不进入文本副本。
- `server/`、`public/__grok/` 和平台辅助代码按项目契约保留，不因本站暂未使用认证/数据库就删除。
- 历史审查文档、截图及其中直接引用的脚本继续保留原路径，避免证据链接失效。
- 2026-10-20 仅把 14 个未被已跟踪文件引用的旧 ZIP、临时 QA 文件和本地报告在 `artifacts/` 内分类移动；不删除任何文件。逐文件哈希和新旧路径保存在本机清单，遇到冲突拒绝覆盖。
- 日常核对只发送 `changes.txt`，全站审查只发送 `1/2/3-*.txt`；同次不重复发送相同内容。

## 本地改动的交付顺序

运行格式、全量测试、类型、lint 与生产构建；涉及页面时复核开发版和构建产物的桌面/手机表现。提交并推送到现有 `main` 后，分别确认 GitHub 验证和 Vercel 部署，再同步文本副本并检查大小、文件数与快照一致性。GitHub CI 日志不替代真实浏览器验证。
